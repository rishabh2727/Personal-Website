## Overall Impression

The portfolio is credible, readable, responsive, and unusually honest. Its biggest weakness is that it describes strong engineering work without visually proving it. A recruiter learns what Rishabh built, but not enough about his ownership, education, co-op experience, or how the systems work.

## What’s Working

- The voice is plainspoken and avoids inflated claims.
- Project descriptions explain engineering decisions rather than merely listing technologies.
- The responsive structure is robust, semantic, and easy to scan.

## Priority Issues

1. **[P1] The site describes work instead of showing it**
   - **Why it matters:** Recruiters cannot quickly distinguish substantial engineering work from a well-written summary.
   - **Fix:** Feature one or two projects with factual artifacts such as an architecture diagram, interface image, or structured explanation of the problem, role, and key decision.
   - **Suggested command:** `/impeccable bolder`

2. **[P1] Hiring evidence is buried**
   - **Why it matters:** The University of Alberta degree and co-op background are strong trust signals, but the first screen does not expose them.
   - **Fix:** Add a concise proof line near the introduction and clarify individual role on team projects.
   - **Suggested command:** `/impeccable layout`

3. **[P2] The visual language does not embody reliable systems**
   - **Why it matters:** The current styling is pleasant but category-generic, so it does not reinforce the backend/system-correctness positioning.
   - **Fix:** Use structured project metadata, system relationships, deliberate hierarchy, and one featured project instead of four equal cards.
   - **Suggested command:** `/impeccable typeset`

4. **[P2] Mobile scanning and the closing action are weak**
   - **Why it matters:** Repeated project cards make the mobile page long, several targets sit below the committed 44px size, and the passive contact section does not create a strong finish.
   - **Fix:** Tighten secondary projects, improve focus/touch states, and create a clear email CTA with GitHub and LinkedIn as secondary actions.
   - **Suggested command:** `/impeccable adapt`

## Persona Red Flags

- **Jordan, first-time visitor:** “RM” and “Notty” are unexplained; GitHub is the only path to deeper evidence.
- **Riley, stress tester:** Team ownership, project status, and implementation boundaries are not stated; inaccessible repositories would leave claims unsupported.
- **Casey, mobile visitor:** Repeated cards require substantial scrolling, and some touch targets fall below 44px.
- **Recruiter or hiring manager:** Role fit is clear, but degree, co-op evidence, strongest-project priority, and an interview-oriented CTA take too long to emerge.

## Minor Observations
